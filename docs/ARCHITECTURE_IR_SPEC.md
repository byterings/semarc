# Architecture IR Specification

Architecture IR is SEMARC's framework-independent internal representation.

It is the bridge between semantic architecture meaning and target-specific generation.

## Purpose

Architecture IR separates:

- semantic meaning
- architecture planning
- implementation strategy
- target code generation

The same IR can be mapped to PHP, FastAPI, or future targets.

## IR Boundary

IR may contain:

- components
- routes
- models
- fields
- relationships
- foreign keys
- migration metadata
- target profile metadata
- dependency graph data

IR must not contain:

- PHP method bodies
- Python imports
- SQLAlchemy syntax
- framework-specific folder names
- template names

## Top-Level Shape

Example:

```json
{
  "project": "BlogAPI",
  "target": "FASTAPI",
  "target_profile": {
    "target": "FASTAPI",
    "generator": "fastapi",
    "framework": "fastapi"
  },
  "config": {
    "database": {
      "engine": "MYSQL"
    }
  },
  "controllers": [],
  "services": [],
  "models": [],
  "middlewares": [],
  "repositories": [],
  "validators": [],
  "relationships": [],
  "foreign_keys": [],
  "migrations": {},
  "routes": [],
  "dependency_graph": {},
  "relationship_graph": {}
}
```

## Component Types

### Controllers

Represents target-neutral handler components.

```json
{
  "name": "AuthController",
  "type": "auth",
  "strategy": "JWT"
}
```

FastAPI may map this to a router. PHP may map it to a controller class.

### Services

Represents reusable backend services.

```json
{
  "name": "TokenService",
  "type": "auth"
}
```

### Models

Represents data models with relationship metadata.

```json
{
  "name": "Post",
  "fields": [
    {"name": "title", "type": "STRING"}
  ],
  "relations": [
    {"source": "User", "type": "HAS_MANY", "target": "Post"}
  ],
  "foreign_keys": [
    {
      "table": "posts",
      "column": "user_id",
      "references_table": "users",
      "references_column": "id"
    }
  ]
}
```

### Repositories

Represents data access components and semantic dependencies.

```json
{
  "name": "UserRepository",
  "model": "User",
  "type": "memory",
  "dependencies": ["PostRepository"]
}
```

### Relationships

Relationship metadata is stored independently of target syntax.

```json
{
  "source": "User",
  "type": "HAS_MANY",
  "target": "Post"
}
```

### Routes

Routes use target-neutral handler descriptors.

```json
{
  "method": "POST",
  "path": "/login",
  "handler": {
    "type": "controller",
    "component": "AuthController",
    "action": "login"
  }
}
```

The `component` and `action` fields describe architecture intent. PHP maps them to a controller object and method call. FastAPI maps them to router functions.

### Foreign Keys

Foreign key metadata is generated by the relationship engine.

```json
{
  "table": "posts",
  "column": "user_id",
  "references_table": "users",
  "references_column": "id",
  "source_model": "User",
  "target_model": "Post"
}
```

### Migrations

Migration metadata is target-neutral.

```json
{
  "tables": [
    {
      "model": "Post",
      "table": "posts",
      "fields": [
        {"name": "title", "type": "STRING"}
      ],
      "foreign_keys": []
    }
  ],
  "foreign_keys": []
}
```

PHP maps this to `.sql` and migration classes.

FastAPI maps this to SQLAlchemy table metadata.

## Target Neutrality

IR describes architecture facts. It does not prescribe code syntax.

Example target mappings:

```text
IR relationship:
User HAS_MANY Post

PHP:
$this->hasMany(Post::class)

FastAPI:
relationship("Post", back_populates="user")
```

## Determinism

IR ordering should be stable after optimization:

- models sorted by name
- repositories sorted by name
- relationships sorted by source, type, target

This supports deterministic generation and testable output.

## Contract Validation

`compiler/contracts.py` validates IR shape before generation.

Checks include:

- required top-level keys
- model structure
- route handler structure
- repository structure
- target-specific leakage markers

Debug mode reports:

```text
[IR Validation]
PASS: No target-specific leakage detected
```
